# Defacing Repeat Batch Design

## Goal

Build a reproducible experiment workflow that compares SimNIBS/CHARM behavior on
intact versus anonymized inputs for one subject (`sub-CCMe`) across two targets
(`left-hippocampus`, `left-m1`) with 10 repeated dataset roots per condition on
HPC.

The scientific comparison is:

- intact condition: CHARM sees the original face in both T1 and T2
- defaced condition: CHARM receives defaced T1 and T2 and must reconstruct the
  missing facial region via its own pipeline

## Scope

In scope:

- generate defaced T1 and T2 from provided intact T1 and T2
- stage four repeat-batch roots:
  - `Left_Hippocampus_Intact`
  - `Left_Hippocampus_Defaced`
  - `Left_M1_Intact`
  - `Left_M1_Defaced`
- create 10 repeat datasets per root using standard `*_Data_XX` naming
- support simulation runs without a custom segmentation input
- support `.nii` and `.nii.gz` subject inputs
- provide an HPC launcher for full reruns across all repeats in one parent root
- document local preparation, upload layout, HPC launch, and downstream usage

Out of scope:

- automatic data upload to HPC
- post-processing redesign
- mesh-reuse reruns

## Scientific / Data Assumptions

- The provided inputs are one intact T1 and one intact T2 for `sub-CCMe`.
- There is no required custom segmentation map for this experiment.
- The experiment should use CHARM-only segmentation and mesh generation for both
  intact and defaced conditions.
- The defaced T2 should be generated by reusing the T1-derived face mask. The
  mask must be resampled from T1 space to T2 space with nearest-neighbor
  interpolation before application.

## Dataset Layout

Each condition root contains 10 repeat roots:

- `Left_Hippocampus_Intact/Left_Hippocampus_Data_01` ... `_10`
- `Left_Hippocampus_Defaced/Left_Hippocampus_Data_01` ... `_10`
- `Left_M1_Intact/Left_M1_Data_01` ... `_10`
- `Left_M1_Defaced/Left_M1_Data_01` ... `_10`

Each repeat root contains one subject:

- `<repeat-root>/sub-CCMe/anat/`

Inside `anat/`, the staged inputs are canonical subject filenames:

- `sub-CCMe_T1w.nii.gz` or `sub-CCMe_T1w.nii`
- `sub-CCMe_T2w.nii.gz` or `sub-CCMe_T2w.nii`

The intact roots receive copies of the original pair. The defaced roots receive
copies of the generated defaced pair, but keep the canonical filenames so the
simulation runner remains condition-agnostic.

No custom segmentation file is required in the staged repeats.

## Defacing Workflow

### T1

Use `fsl_deface` as the supported defacing backend. For T1:

- run `fsl_deface <intact_t1> <defaced_t1>`
- request the saved defacing mask via `-d <mask_path>`
- optionally save QC outputs for local inspection

### T2

`fsl_deface` is explicitly a T1-oriented tool, so T2 defacing should not call
`fsl_deface` independently. Instead:

1. load the saved T1 defacing mask
2. resample the mask to T2 space with nearest-neighbor interpolation
3. zero T2 voxels outside the inverse kept-region exactly as done for T1
4. save the resulting defaced T2

This keeps both modalities defaced by the same anatomical face-removal region.

## Simulation Runner Changes

The current runner assumes:

- T1 and T2 must be uncompressed `.nii`
- a custom segmentation file always exists
- CHARM output is always merged with that custom segmentation and remeshed

That is incompatible with this experiment.

The updated behavior should be:

1. resolve T1/T2 inputs from either `.nii` or `.nii.gz`
2. detect whether a custom segmentation file exists
3. if custom segmentation exists:
   - keep the current merge-and-remesh behavior
4. if custom segmentation does not exist:
   - run CHARM normally
   - skip the merge/remesh replacement path
   - continue using the CHARM-produced mesh directly

This “pure CHARM” path is the required mode for the defacing experiment.

## HPC Execution Model

The standard single-root array runner is per dataset root and per subject list,
so it is not sufficient for a parent root containing 10 repeat datasets.

The experiment should use a manifest-driven launcher that:

- discovers repeat roots under one condition parent
- writes one manifest row per repeat/subject task
- submits chunked Slurm arrays for those manifest rows
- sets `TI_SIM_ROOT` to the repeat root for each task
- calls the existing multi-core simulation runner in single-subject mode
- keeps the existing validation and requeue logic
- does full reruns only; no mesh reuse flag

This launcher should work identically for:

- `Left_Hippocampus_Intact`
- `Left_Hippocampus_Defaced`
- `Left_M1_Intact`
- `Left_M1_Defaced`

with montage presets:

- `left-hippocampus`
- `left-m1`

## CLI / Tooling Additions

### Defacing prep CLI

Add a prep command in `defacing_experiment/` that:

- validates intact T1/T2 inputs
- generates defaced T1/T2 outputs
- creates the four experiment parent roots
- populates 10 repeat datasets per root
- writes manifests summarizing staged files and repeat roots

### HPC launch wrapper

Add a submit wrapper in `CamCan_Experiment/HPC_scripts/` that:

- accepts one condition parent root and one montage preset
- writes or consumes a task manifest
- submits one or more Slurm array chunks

## Testing Strategy

Add tests for:

- subject input path resolution over `.nii` and `.nii.gz`
- optional custom segmentation behavior
- defaced T2 mask resampling/application behavior
- repeat-root staging and naming
- parent-root manifest generation
- HPC launcher source-level expectations and shell syntax

## Documentation

Provide user-facing documentation that covers:

- local prerequisites
- generating defaced T1/T2 from intact inputs
- building the four experiment roots
- exactly what to upload to HPC
- launch commands for the two targets
- expected output locations
- how to run downstream post-processing per condition root

## Success Criteria

The experiment is ready when:

- one command can generate the defaced pair and stage all four experiment roots
- the simulation runner works with no custom segmentation file
- a launcher can submit all 10 repeats for one condition root on HPC
- documentation is sufficient for re-running the full workflow without code
  inspection
